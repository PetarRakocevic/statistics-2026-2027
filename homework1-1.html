1 Theory

An elliptic curve over a prime field Fp is the set of points (x,y) satisfying y² = x³ + ax + b (mod p), plus a point at infinity O that acts as the identity. Ethereum uses secp256k1, where a = 0, b = 7 and p = 2256 − 232 − 977. Our toy curve keeps the same shape, y² = x³ + 7 (mod 17), with base point G = (1,5). Check: 1³+7 = 8 and 5² = 25 ≡ 8 (mod 17).

Point addition uses the chord-and-tangent rule: for P≠Q the slope is λ = (y₂−y₁)/(x₂−x₁), for P=Q it is λ = 3x²/2y. Then x₃ = λ²−x₁−x₂ and y₃ = λ(x₁−x₃)−y₁, all mod p, where division means multiplication by a modular inverse. Scalar multiplication is repeated addition: Q = kG. The public key is Q, the private key is k. The reverse problem, finding k from G and Q, is the Elliptic Curve Discrete Logarithm Problem (ECDLP). On 17 elements it is trivial to brute-force; on 256 bits there is no known feasible attack.

Double-and-add computes kG in about log₂k doublings plus at most as many additions, instead of k−1 additions. For k = 6 = 110₂: start with G, double → 2G, add G → 3G, double → 6G.

2 Implementation

const p=17, b=7;                       // curve y^2 = x^3 + 7 (mod p)
const mod=(a)=>((a%p)+p)%p;
const pw=(x,e)=>{let r=1;x=mod(x);while(e){if(e&1)r=mod(r*x);x=mod(x*x);e>>=1}return r};
const inv=(x)=>pw(x,p-2);              // Fermat inverse
function add(P,Q){                     // null = point at infinity O
  if(!P)return Q; if(!Q)return P;
  if(P[0]===Q[0] && mod(P[1]+Q[1])===0)return null;
  const l = P[0]===Q[0] ? mod(3*P[0]*P[0]*inv(2*P[1])) : mod((Q[1]-P[1])*inv(Q[0]-P[0]));
  const x=mod(l*l-P[0]-Q[0]); return [x, mod(l*(P[0]-x)-P[1])];
}
function mul(k,P){let R=null,A=P;while(k){if(k&1)R=add(R,A);A=add(A,A);k>>=1}return R}

6 Discussion

Properties that matter for a one-way function

One-wayness / hardness of inversion is the defining property: k→kG is cheap, Q→k is believed hard (ECDLP). Determinism is needed so the same k always gives the same public key. Apparent uniformity of Q over the group is desirable, since structure in x or y would leak information about k. In the toy run the x and y histograms are roughly flat but visibly lumpy; with so few points a chi-square test has little power, and lumps are expected from small samples.

Properties that belong to hash functions

Avalanche (flip one input bit, about half of output bits change) is a design goal of hashes and ciphers. Scalar multiplication is not built for it: kG and (k+1)G differ by exactly G, a fixed group step, and the output has algebraic structure (2G, 4G, 8G are chained by doubling). Related-key structure of this kind is exactly why k must be random and never derived by a weak rule. A measured bit-flip distance near half of the output bits is nice but not what security rests on. Collision resistance and preimage resistance for arbitrary-length input are hash notions: EC multiplication takes a bounded scalar and has an algebraic homomorphism, (a+b)G = aG + bG, which a hash must never have. That homomorphism is what makes signatures, key aggregation and BIP-32 public derivation possible.

Caveats

On a group of about 20 points every statistic is dominated by finite-size effects, and bit-level measures over 5-bit coordinates cannot say anything about 256-bit behaviour. The correlation between k and x is also not a security measure, since the sequence kG is periodic with period n. The exercise is a model for understanding, as the assignment notes.
